# Cube ID, этап 1: короткие имена `@name`

Дизайн согласован с владельцем 2026-09-29 по частям в чате. Cube ID — это
экосистема из трёх этапов, у каждого своя спецификация:

1. **Имена `@name`** — этот документ.
2. Вход в сторонние сервисы через Cube ID — позже, строится на этом.
3. Одна личность на нескольких устройствах — последним, это переделка
   протокола.

Сейчас начать чат можно, только если человек был рядом по Bluetooth или
передал свою карточку (`cubechat:c1:`, QR). Этап 1 даёт третий путь: знать
имя.

---

## Главная идея

Имя указывает на **подписанную карточку**, которая уже существует.

Карточка — это `PeerAnnouncement` (`lib/core/transport/announcement.dart`):
X25519-ключ, Ed25519-ключ подписи, подписанный prekey, Nostr-ключ, никнейм и
дайджест аватара под одной подписью Ed25519. Её уже передают QR-кодом и
текстом (`lib/core/transport/contact_card.dart`), и приложение уже умеет её
импортировать (`ContactCard.parse` → `PeerAnnouncement.verifyAndDecode`).

Реестр хранит связку **имя → байты карточки** и ничего больше. Найти
`@dima` значит получить его карточку и импортировать её тем же путём, что и QR:

- **Сервер не может подменить собеседника.** Он отдаёт байты, подпись
  проверяет телефон; карточка с чужой подписью отвергается так же, как
  испорченный QR.
- **Новых типов сообщений в mesh нет.** Ни `InnerPayloadType`, ни `FrameType`,
  ни версии манифеста не меняются; старые сборки ничего не замечают.
- Сервер может соврать только одним способом: отдать под именем `@dima`
  чужую, но честно подписанную карточку. От этого защищает то же, что и для
  QR: человек, добавленный по имени, считается непроверенным, пока отпечатки
  не сверены (экран проверки).

## Решения владельца

| Вопрос | Решение |
|---|---|
| Обязательно ли имя | Нет. Берётся в профиле, когда захочется; онбординг не меняется |
| Формат | `[a-z0-9_]`, 3–20 символов, без учёта регистра (хранится в нижнем) |
| Запрещённые имена | Служебные (`admin`, `support`, `cubechat`, `root`, `help`, …) и мат (стемы из `lib/features/moderation/domain/profanity.dart`) |
| Смена имени | Можно; старое 30 дней указывает на владельца, потом освобождается |
| Потерян ключ | Имя освобождается после 6 месяцев без продления; экстренное стирание освобождает сразу |
| Почта для восстановления | Необязательная, подэтап 1б (ниже) |
| Кто может писать | Все (по умолчанию) / через запрос / никто — см. §3 |
| Где хранить | Реестр на нашем сервере, совместимый со стандартом Nostr NIP-05 |

Отвергнуто: имя как подписанное событие в Nostr без реестра (нет гарантии
уникальности — два `@dima`), блокчейн (платно, медленно), обязательная почта
или телефон (это аккаунт, против идеи cubechat).

## 1. Сервер `cubechat-id`

### Где живёт

- Отдельный сервис `cubechat-id` в `id/` рядом с `push/`: Node ≥ 22, тесты
  `node --test`. Не внутри `push/src/index.js` — тот уже ~2 000 строк и
  отвечает за другое.
- Хранилище — SQLite через встроенный `node:sqlite` (Node 22.23 на
  droplet). Одна база `names.db`.
- Адрес `https://id.cubechat.tech`. Полное имя — `dima@id.cubechat.tech`,
  в приложении показывается `@dima`. Поддомен нужен потому, что
  `cubechat.tech` — GitHub Pages (статический сайт), а NIP-05 запрещает
  клиентам следовать переадресации.
- Caddy получает ещё один блок `id.cubechat.tech { reverse_proxy
  127.0.0.1:<port> }`. Блок добавляется в `push/deploy/Caddyfile` и в живой
  `/etc/caddy/Caddyfile` одинаково; перед заменой — дифф и копия
  (история с потерянным блоком ретранслятора 2026-09-24).
- От владельца: DNS-запись A `id.cubechat.tech` → 209.38.225.225.

### Данные

```
names(
  name        TEXT PRIMARY KEY,   -- нижний регистр
  nostr_pub   TEXT NOT NULL,      -- hex, владелец; один ключ — одно имя
  card        BLOB NOT NULL,      -- байты PeerAnnouncement, как есть
  reach       TEXT NOT NULL,      -- 'all' | 'request' | 'none'
  created_at  INTEGER, renewed_at INTEGER
)
held(                             -- старое имя после смены, 30 дней
  name TEXT PRIMARY KEY, nostr_pub TEXT, until INTEGER
)
revoked(                          -- отозвано модератором
  name TEXT PRIMARY KEY, reason TEXT, at INTEGER
)
```

Уникальный индекс на `names.nostr_pub`: у ключа не больше одного
действующего имени.

### Действия — подписанные события Nostr

Как регистрация пушей (`REGISTER_KIND = 24242` в `push/src/index.js`):
каждое действие — Nostr-событие своего вида, подписанное Nostr-ключом
владельца (BIP-340). Вид **24243**, `content` — JSON:

| `op` | Поля | Что делает |
|---|---|---|
| `claim` | `name`, `card` (base64url) | Занять свободное имя |
| `rename` | `name`, `card` | Новое имя; старое уходит в `held` на 30 дней |
| `update` | `card`, `reach` | Обновить карточку (сменился ник, аватар, prekey) или настройку |
| `renew` | — | Продлить; приложение шлёт раз в неделю |
| `release` | — | Освободить имя сразу (в том числе при экстренном стирании) |

Сервер принимает событие, только если:

1. id и подпись события верны (как `verifyEvent` в push);
2. `created_at` не старше 5 минут и не в будущем больше чем на 1 минуту;
   id события не встречался (защита от повтора, как в push);
3. карточка разбирается, её подпись Ed25519 верна, и **Nostr-ключ внутри
   карточки равен `pubkey` события** — нельзя повесить на своё имя чужую
   карточку;
4. для `claim` и `rename`: событие несёт proof-of-work по NIP-13 не меньше
   **16 бит** (около секунды на телефоне; значение — константа, подбирается
   на реальном телефоне, если выйдет дольше 3 с — снижаем);
5. имя проходит правила: формат, служебные слова, мат, не отозвано, не
   занято, не удерживается за другим ключом;
6. лимит частоты: не больше 5 `claim`/`rename` в час с одного IP и одного
   ключа.

Разбор карточки на сервере — отдельный модуль, тесты сверяют его с
байтами, которые выдаёт Dart-код (фикстура из `test/`).

### Чтение

- `GET /.well-known/nostr.json?name=dima` — стандарт NIP-05:
  `{"names":{"dima":"<nostr hex>"}}`. Так имя признают другие Nostr-клиенты
  и этап 2. Для `reach = 'none'` — пустой ответ.
- `GET /v1/card/dima` — `{"name","card","reach"}`, карточка в base64url.
  Для `reach = 'none'`, отозванного или несуществующего — 404, без различия
  причин.
- `GET /v1/available/dima` — свободно ли и почему нет (`taken`, `reserved`,
  `invalid`). Лимит частоты на IP, чтобы не перебирать базу быстро.
- Имя из `held` отдаёт карточку владельца 30 дней.

Обратного поиска «ключ → имя» нет.

### Сроки

- `renewed_at` старше 6 месяцев → имя освобождается (проверка раз в сутки).
- `held` старше 30 дней → удаляется.
- Ежедневная копия `names.db` в `/root/backups/` с хранением 14 дней.
  Каждая запись содержит подписанную карточку, поэтому подделку при
  восстановлении видно.

### Модерация

- Жалоба на оскорбительное имя идёт через существующий `/report`
  (контекст `name`).
- Админ-API на localhost, как у жалоб: `POST /admin/revoke {name, reason}`.
  Отозванное имя освобождается у владельца и больше не выдаётся.
- Бот `cubechat-bot` получает кнопку «Отозвать имя».
- Глобальный бан по ключу (`/banned`) действует и здесь: забаненный ключ не
  может занять имя, его имя отзывается.

### `/health`

`{"ok":true,"version":"…","names":N}` — как у push, чтобы деплой было видно.

## 2. Приложение: имя

### Профиль → Cube ID

- Поле ввода с проверкой на лету (формат локально, занятость —
  `/v1/available`, с задержкой 400 мс после ввода).
- «Заняти» → proof-of-work в фоновом isolate → `claim` → на экране `@dima`.
- Уже есть имя: «Змінити», «Звільнити», «Поділитися». Делится текст
  «@dima у cubechat» и ссылка `https://cubechat.tech/u.html#dima` —
  статическая страница лендинга (GitHub Pages не умеет маршрут `/@dima`),
  которая показывает имя, подсказку «знайдіть @dima в cubechat» и ссылки на
  магазины. Открытие ссылки прямо в приложении — не в этом этапе.
- Хранится локально в зашифрованном боксе настроек: имя, время последнего
  продления.

### Продление и обновление карточки

- При запуске и при возврате из фона: если с `renewed_at` прошло больше
  7 дней — `renew`.
- Когда меняется собственная карточка (ник, аватар, ротация prekey) и имя
  есть — `update`. Иначе поиск по имени отдавал бы старый ник и старый
  prekey.
- Ошибки сети не показываются: повтор при следующем запуске.

### Поиск

- «Новий чат» → «Знайти за @іменем» → `GET /v1/card/<name>` → карточка →
  `ContactCard`-путь импорта (`messaging_service.dart`, место, где сейчас
  разбирается вставленная карточка) → экран контакта с кнопкой «Написати».
- Контакт помечается как найденный по имени; имя сохраняется как подпись к
  контакту (показывается `@dima` под ником). Проверенным он не считается.
- 404 → «Не знайдено». Сеть недоступна → «Немає інтернету».

### Экстренное стирание

Перед стиранием ключей — `release` с таймаутом 3 с. Не успело — имя
освободится через 6 месяцев; стирание не ждёт сеть дольше.

## 3. Кто может писать мне через интернет

Новая настройка в «Профіль → Приватність»: **«Хто може писати мені з
інтернету»**.

- **Усі** (по умолчанию) — как сейчас.
- **Через запит** — первое сообщение от ключа, которого нет в контактах,
  попадает в новую папку **«Запити»** в списке чатов. Пока не нажато
  «Прийняти»: отправитель не получает отметку «прочитано», не может
  позвонить (приглашение звонка от него отклоняется как «занято»), медиа не
  скачивается автоматически. «Прийняти» переносит чат в обычные, «Видалити»
  удаляет его, «Заблокувати» — блокирует.
- **Ніхто** — такие сообщения отбрасываются при получении, а реестр перестаёт
  отдавать карточку по имени (`reach = 'none'`).

Почему настройка про всех незнакомцев из интернета, а не только «по
имени»: телефон не может отличить, нашли его по имени или по QR-карточке —
в обоих случаях приходит сообщение через Nostr от незнакомого ключа. Честная
настройка — про источник, который телефон действительно видит.

С Bluetooth-соседями всё остаётся как есть: настройка их не касается.
«Контакт» здесь — это `KnownPeer`, с которым есть история и в которой
пользователь писал сам (`hasWrittenIn` из фильтра модерации), либо принятый
запрос.

## 4. Подэтап 1б: почта для восстановления

Выпускается после имён, отдельным планом.

- В Cube ID можно привязать почту. Сервер хранит её, шлёт письмо со ссылкой
  подтверждения.
- Восстановление: на новом телефоне «Відновити ім’я через пошту» → письмо со
  ссылкой → через **48 часов** имя переходит на новый ключ.
- Живой старый ключ может отменить перенос в эти 48 часов (подписанный
  `cancel-recovery`); приложение со старым ключом показывает предупреждение.
- Контакты при переносе видят существующее предупреждение «ключ
  співрозмовника змінився».
- Нужен сервис отправки писем — новый сторонний получатель данных; выбор
  сервиса и правки юридических документов — в плане 1б.

## 5. Юридические документы

Появляется новый запрос к серверу и новые данные на нём. По правилу
`CLAUDE.md` меняются вместе с кодом:

- `docs/legal/privacy-policy.uk.md` и `.en.md`: что хранит `id.cubechat.tech`
  (имя, карточка с открытыми ключами, ником и дайджестом аватара, настройка
  доступности, время продления), что IP используется только для лимитов и не
  пишется в базу, сроки (30 дней, 6 месяцев), что имя публично и находится
  кем угодно, как удалить (освободить имя).
- `docs/legal/store-disclosures.md`: App Privacy / Data safety —
  «User ID» (имя) связан с пользователем, не для трекинга.
- Страница политики на лендинге (`public/privacy.html`) — обновить тем же
  текстом.

## 6. Проверка

**Сервер (`node --test` в `id/`):**
- разбор и проверка карточки на фикстуре из Dart; карточка с чужим
  Nostr-ключом и с испорченной подписью отвергается;
- правила имени: формат, регистр, служебные, мат с исключениями
  (`сукня` — можно);
- proof-of-work: ниже порога — отказ;
- повтор события и старое событие — отказ;
- `rename` держит старое имя 30 дней и отдаёт по нему карточку;
- истечение 6 месяцев и 30 дней (часы в тестах подменяются);
- `reach = 'none'` → 404 и пустой NIP-05;
- `revoke` и бан по ключу.

**Приложение (`flutter test`):**
- правила имени локально совпадают с серверными (общая таблица случаев);
- поиск → импорт карточки → контакт помечен «по имени», не проверен;
- подменённая сервером карточка отвергается;
- `update` уходит при смене ника и аватара;
- настройка «Через запит»: сообщение незнакомца уходит в «Запити», без
  отметки «прочитано», звонок отклоняется; «Прийняти» переносит чат;
- «Ніхто»: сообщение незнакомца отброшено, от контакта — доходит;
- экстренное стирание вызывает `release` и не ждёт больше 3 с.

**Вживую, на двух телефонах:** занять имя на одном, найти и написать с
другого; сменить имя — старое находит 30 дней; «Ніхто» — поиск не находит.

## 7. Что не входит

- Вход в сторонние сервисы (этап 2) и несколько устройств (этап 3).
- Платные или короткие (1–2 символа) имена.
- Обратный поиск по ключу, каталог имён, поиск по части имени.
- Проверенные (с галочкой) имена организаций.
