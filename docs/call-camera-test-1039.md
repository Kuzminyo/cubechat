## Что показали логи
- Оба вызова остановились через ~12.3 секунды на ICE gathering, до отправки invite.
- Подписанный доступ TURN уже выдавался за 201–277 мс.
- На Android задний сенсор 2 сообщил `No flash unit`.
- Подготовка камеры занимала 504–701 мс, начало записи — 676–1165 мс.
- В одном логе preview 960×720, в другом 1440×1080.
- Скрин: build avg 1.0 / p90 1.4 мс, raster avg 4.1 / p90 5.8 мс. Он не измеряет задержку захвата камеры.

## Изменения
- SDP отправляется после получения рабочего relay-кандидата и короткого окна сбора остальных, не ожидая зависших интерфейсов до общего таймаута.
- TURN выдаёт `push.cubechat.tech:3478` вместо IPv4-литерала. TCP и UDP allocation проверены внешним запросом с настоящими временными credentials. Секрет не менялся.
- CameraX открывает видеосессию сразу для veryHigh; лишние photo/analysis bind и перестроение preview при stop убраны.
- События Start/Finalize принадлежат конкретной записи. Ошибка до Start и поздние события отменённой записи не удерживают следующую.
- Persistent recording закрывается при dispose даже после неудачного старта.
- Задняя камера с flash предпочитается вспомогательному широкоугольному сенсору без flash. Отказ torch больше не выдаётся за включённую подсветку.
- Запрошены 1080 по короткой стороне, 60 fps, 5 Mbps; автоэкспозиция +1 EV сохранена. Ранее код снижал разрешение до 720 и fps до 30 при плохом свете.
- Android использует поддерживаемый continuous-video AF, iOS — smooth continuous AF на поддерживаемых устройствах.

## Проверка на телефонах
1. Обновить обе стороны; не удалять приложение, чтобы сохранить ключи и чаты. На iPhone собрать этот же код через macOS/Xcode или существующий iOS CI. Windows APK не обновляет iPhone.
2. Полностью перезапустить приложения для получения нового TURN-адреса. Оба приложения держать открытыми.
3. Позвонить Android → iPhone, затем обратно. Проверить звук в обе стороны, mute, динамик, завершение и немедленный повтор.
4. Повторить между Wi-Fi и мобильной сетью.
5. Записать/отменить кружок 5 раз подряд. Каждый раз проверить первый кадр, звук, front/back и фонарик сзади. Отдельно сохранить один клип и проверить фактические fps/размер файла.
6. Проверить фокус: лицо на обычном расстоянии, затем предмет на задней камере. Не требовать резкости ближе минимальной дистанции фокуса сенсора.
7. Если проблема остаётся — сразу экспортировать логи с обеих сторон. Для звонка нужны строки `usable relay candidate`, `offer ready`, `ice`, `connection`; для камеры — `start`, `flip`, `camera reported`, `cancel`.

Границы проверки: доступ TURN и программная логика проверены, реальный разговор и качество камер требуют двух устройств. Подключённых USB-устройств при сборке не было. Запрос 1080/60 не доказывает, что конкретный сенсор выдаёт эту комбинацию; нативная система может выбрать поддерживаемую. Физический шум слабого освещения программной настройкой полностью не устраняется.
